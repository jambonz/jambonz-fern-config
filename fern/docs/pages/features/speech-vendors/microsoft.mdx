---
title: Microsoft Azure
subtitle: Speech-to-text and text-to-speech models, options and notes for Microsoft Azure Speech.
---

jambonz supports Microsoft Azure Speech for both **speech-to-text** and **text-to-speech** (vendor `microsoft`). The speech credential holds the subscription key and region. It can also point to a custom speech model, a custom neural voice, or a Speech container you run yourself.

## Speech-to-text

```json
{
  "verb": "gather",
  "input": ["speech"],
  "actionHook": "/gather",
  "recognizer": {
    "vendor": "microsoft",
    "language": "en-US",
    "hints": ["jambonz", "drachtio"],
    "azureOptions": {
      "speechSegmentationSilenceTimeoutMs": 800
    }
  }
}
```

### Models

Azure has no model names to choose from. jambonz uses Azure's base model for the `language` you set. See Microsoft's [supported languages](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/language-support?tabs=stt).

To use a [custom speech](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/custom-speech-overview) model, enter its endpoint ID on the speech credential in the portal, or set `recognizer.azureSttEndpointId` on the verb. The verb's value wins.

### Options

These generic `recognizer` properties apply:

<ParamField path="language" type="string" required={false}>
  The language code, e.g. `en-US`.
</ParamField>

<ParamField path="hints" type="array" required={false}>
  Phrases to boost, sent to Azure as a phrase list. Object hints are accepted, but only the `phrase` is used.
</ParamField>

<ParamField path="profanityOption" type="string" required={false}>
  How Azure handles profanity: `masked`, `removed` or `raw`.
</ParamField>

<ParamField path="initialSpeechTimeoutMs" type="number" required={false}>
  Milliseconds of initial silence before Azure gives up on the utterance.
</ParamField>

<ParamField path="requestSnr" type="boolean" required={false}>
  Ask Azure to include the signal-to-noise ratio in results.
</ParamField>

<ParamField path="punctuation" type="boolean" required={false}>
  Set to `false` to strip punctuation from transcripts. jambonz removes it; Azure still punctuates.
</ParamField>

<ParamField path="azureSttEndpointId" type="string" required={false}>
  Endpoint ID of a custom speech model.
</ParamField>

<ParamField path="azureServiceEndpoint" type="string" required={false}>
  A `wss://` URL to connect to instead of Azure's regional endpoint, e.g. for a Speech container or private endpoint.
</ParamField>

Put these in `recognizer.azureOptions`:

<ParamField path="speechSegmentationSilenceTimeoutMs" type="number" required={false}>
  Milliseconds of silence that end a phrase. See Microsoft's [silence handling](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-recognize-speech#change-how-silence-is-handled).
</ParamField>

<ParamField path="speechRecognitionMode" type="string" required={false}>
  `CONVERSATION`, `DICTATION` or `INTERACTIVE`. Azure's conversation mode is used when unset.
</ParamField>

<ParamField path="postProcessing" type="string" required={false}>
  Azure post-processing option, sent as the `postprocessing` query parameter.
</ParamField>

<ParamField path="audioLogging" type="boolean" required={false}>
  Ask Azure to store the audio for diagnostics. See Microsoft's [audio logging](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/logging-audio-transcription).
</ParamField>

<ParamField path="languageIdMode" type="string" required={false}>
  `AtStart` or `Continuous`. See the note below.
</ParamField>

### Notes

- **`altLanguages` and `languageIdMode` have no effect.** jambonz accepts them but doesn't send them to Azure, so there is no language identification. Recognition uses `language` only.
- **Results always use Azure's detailed format.** `outputFormat` is ignored. Transcripts include confidence scores from Azure's n-best list.
- **Ignored generic properties.** `profanityFilter` (use `profanityOption`), `hintsBoost`, `model`, `diarization` and `words` have no effect with Azure.
- **Your own Speech container or private endpoint.** Enable the on-premises option on the speech credential and enter the STT URL, or set `azureServiceEndpoint` on the verb.

## Text-to-speech

```json
{
  "verb": "say",
  "text": "Thanks for calling, how can I help you today?",
  "synthesizer": {
    "vendor": "microsoft",
    "language": "en-US",
    "voice": "en-US-AvaMultilingualNeural"
  }
}
```

### Models and voices

Choose a voice by name in `synthesizer.voice`, such as `en-US-AvaMultilingualNeural`. See Microsoft's [voice list](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/language-support?tabs=tts).

For a [custom neural voice](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/custom-neural-voice), enter its deployment ID on the speech credential, or set `synthesizer.options.deploymentId` on the verb.

### Options

Pass these in `synthesizer.options`. They are only needed for a custom neural voice.

<ParamField path="deploymentId" type="string" required={false}>
  Deployment ID of a custom neural voice.
</ParamField>

<ParamField path="apiKey" type="string" required={false}>
  Subscription key for the custom voice's Speech resource. Set this whenever you set `deploymentId`.
</ParamField>

<ParamField path="region" type="string" required={false}>
  Region of the custom voice's Speech resource. Defaults to the credential's region.
</ParamField>

<ParamField path="voice" type="string" required={false}>
  Voice name of the custom voice. Defaults to `synthesizer.voice`.
</ParamField>

These generic synthesizer properties apply:

- `voice`: required.
- `language`: required.

### Notes

- **SSML.** Text that starts with a bare `<speak>` tag is rebuilt: jambonz adds the required namespaces and the language, and wraps the content in a `<voice>` element for the selected voice, so don't add your own `<voice>` element. Text that starts with `<speak` plus attributes is sent unchanged, so it must be complete SSML.
- **Custom neural voices don't play on calls yet.** The media server doesn't send the deployment ID to Azure, so `deploymentId` and a credential's custom voice deployment ID currently take effect only when jambonz pre-caches a prompt.
- **No TTS streaming.** Microsoft works with `say`, but not with [TTS streaming](/guides/features/tts-streaming) or the `agent` verb.
- **Barge-in costs a reconnect.** Azure's streaming protocol has no cancel message, so jambonz drops and reopens the connection when the caller interrupts.
