---
title: Transfer
subtitle: Hand a call off to another destination — blind, or warm parked/three-way — with built-in failure handling
---

The `transfer` verb packages the common transfer choreographies into a single declarative
verb, so you don't have to orchestrate dial/refer, hold music, briefing, confirmation
gates and fallback routing by hand. It covers two broad modes:

- **blind** — hand the call off immediately, without waiting for the destination to accept. Implemented either as a SIP REFER (`blindMethod: 'refer'`) or as a bridged outbound call (`blindMethod: 'dial'`).
- **warm** — let the application brief the destination before the caller is connected. The caller is either *parked* (on hold, `callerPresent: false`) or joined into a *three-way* conference (`callerPresent: true`).

When the transfer does not complete normally (no answer, busy, declined, error), a
configurable **disposition** decides what happens to the caller — return them to the
application, send them to voicemail, or hang up.

```json
{
  "verb": "transfer",
  "mode": "blind",
  "target": [
    { "type": "phone", "number": "+15085551212" }
  ]
}
```

A warm, parked transfer with a spoken brief, hold music, and a fallback when nobody answers:

```json
{
  "verb": "transfer",
  "mode": "warm",
  "callerPresent": false,
  "target": [
    { "type": "phone", "number": "+15085559876" }
  ],
  "brief": {
    "text": "I have a customer on the line who needs help with their account."
  },
  "onHoldHook": "/hold-music",
  "disposition": {
    "onNoAnswer": "return",
    "onBusy": "return"
  },
  "actionHook": "/transfer-complete"
}
```

## Parameters

<ParamField path="mode" type="string" required={true}>
  `blind` or `warm`. `blind` hands the call off immediately without waiting for the
  destination to accept; `warm` lets the application brief the destination before the
  caller is connected.
</ParamField>

<ParamField path="target" type="array" required={true}>
  One or more call [destinations](/verbs/verbs/dial#target-types) (same shape as the `dial`
  verb's target). All targets are attempted simultaneously and the first to answer wins.
</ParamField>

<ParamField path="blindMethod" type="string" required={false} default="refer">
  `blind` only. `refer` sends a SIP REFER to the remote end; `dial` places a bridged
  outbound call. This is **not** auto-detected — set it explicitly to `dial` when REFER is
  not appropriate (e.g. transferring to a PSTN number that the upstream carrier won't REFER).
</ParamField>

<ParamField path="callerPresent" type="boolean" required={false} default="false">
  `warm` only. When `true`, the caller is added to a three-way conference and can hear the
  brief; when `false`, the caller is parked (on hold) and does not hear the conversation
  between the application and the destination.
</ParamField>

<ParamField path="callerId" type="string" required={false}>
  Caller ID presented to the transfer destination.
</ParamField>

<ParamField path="onHoldHook" type="string" required={false}>
  `warm` + parked only (`callerPresent: false`). A webhook returning verbs to run for the
  parked caller while the destination is briefed — e.g. `play` hold music. Ignored when
  `callerPresent` is `true`.
</ParamField>

<ParamField path="timeout" type="number" required={false} default="30">
  Seconds to wait for the destination to answer before applying the `onNoAnswer`
  disposition.
</ParamField>

<ParamField path="brief" type="object" required={false}>
  `warm` only. The literal spoken summary delivered to the destination (human) before the
  caller is connected.
</ParamField>

<ParamField path="brief.text" type="string" required={true}>
  The briefing text spoken to the destination.
</ParamField>

<ParamField path="brief.synthesizer" type="object" required={false}>
  Optional voice/vendor for the brief (a [synthesizer](/verbs/verbs/synthesizer) object).
  Defaults to the session synthesizer.
</ParamField>

<ParamField path="confirm" type="object" required={false}>
  Optional human-side acceptance gate. The destination hears a prompt and must press the
  specified digit to accept. A wrong digit, a timeout, or a hangup is treated as a
  `decline`.
</ParamField>

<ParamField path="confirm.prompt" type="string" required={true}>
  Text or URL of the prompt played to the destination.
</ParamField>

<ParamField path="confirm.digit" type="string" required={true}>
  Single DTMF digit the destination must press to accept the transfer.
</ParamField>

<ParamField path="amd" type="object" required={false}>
  `warm` only. Optional [answering-machine detection](/verbs/verbs/dial) run on the
  destination leg (same `amd` shape as the `dial` verb). Off by default; a `machine`
  result is treated as a `decline`.
</ParamField>

<ParamField path="disposition" type="object" required={false}>
  Per-outcome fallback actions when the transfer does not complete normally. Each key
  accepts `return`, `voicemail`, or `hangup` and defaults to `return`.
</ParamField>

<ParamField path="disposition.onNoAnswer" type="string" required={false} default="return">
  Action when the destination does not answer within `timeout`.
</ParamField>

<ParamField path="disposition.onBusy" type="string" required={false} default="return">
  Action when the destination returns busy.
</ParamField>

<ParamField path="disposition.onDecline" type="string" required={false} default="return">
  Action when the destination declines — the `confirm` gate failed, AMD detected a
  machine, or the destination explicitly rejected the call.
</ParamField>

<ParamField path="disposition.onFailure" type="string" required={false} default="return">
  Action when a protocol-level error occurs on the destination leg.
</ParamField>

<ParamField path="disposition.voicemailUrl" type="string" required={false}>
  SIP URI or HTTP URL to route the caller to voicemail. **Required** whenever any
  disposition value is `voicemail`.
</ParamField>

<ParamField path="actionHook" type="string" required={false}>
  Fires when the transfer resolves — whether the call was bridged, returned to the caller,
  sent to voicemail, or failed. See [actionHook properties](#actionhook-properties).
</ParamField>

<ParamField path="eventHook" type="string" required={false}>
  Optional hook for in-progress transfer lifecycle events. See
  [eventHook events](#eventhook-events).
</ParamField>

<ParamField path="id" type="string" required={false}>
  An optional unique identifier for this verb instance.
</ParamField>

## actionHook properties

When the transfer resolves, the **actionHook** is called with these additional parameters
(alongside the standard call attributes):

- `transfer_result` — one of:
  - `bridged` — the caller and destination were connected and the transfer completed.
  - `returned` — the transfer did not connect and the caller was returned to the application (control falls through to subsequent verbs, or to the verbs returned by the actionHook).
  - `failed` — the transfer ended on a `hangup` disposition or a fatal error.
- `transfer_reason` — the underlying cause:
  - `completed` — destination answered and the call bridged.
  - `no-answer` — destination did not answer within `timeout`.
  - `busy` — destination returned busy.
  - `declined` — `confirm` gate failed, AMD detected a machine, or the destination rejected.
  - `caller-abandoned` — the caller hung up before the transfer completed.
  - `error` — a protocol-level error on the destination leg.

## eventHook events

If `eventHook` is set, jambonz posts the following lifecycle events. Each payload carries
the standard call attributes plus an `event_type` and event-specific fields:

- `transfer.initiated` — fired at the start; includes `mode` and `callerPresent`.
- `transfer.bridged` — caller and destination connected.
- `transfer.returned` — transfer did not connect; includes `transfer_reason`.
- `transfer.failed` — transfer ended on failure; includes `transfer_reason`.

eventHook failures never interrupt the transfer.

## Transfer-to-human from a conversational agent

If you want a voice agent to hand off to a human as a tool call, you do not use the
`transfer` verb directly — instead add a declarative `handoff` block to the
[agent](/verbs/verbs/agent#transfer-to-human-handoff) or [llm](/verbs/verbs/llm#transfer-to-human-handoff)
verb. The runtime injects a `transfer_to_human` tool and runs this same transfer
choreography when the model calls it.

## Live Call Control

You can also inject a transfer into an in-progress call via the REST API by issuing an
`updateCall` request with a `transfer` body — useful for parking a caller and then
transferring them from an external trigger. See the
[REST Call Control](/reference/rest-call-control) reference.
